# 今日研究 brief（2026-06-22）

## 研究范围

- 主题：AI 自动化落地能力升级（多模型浏览器自动化、Agent 记忆框架、可本地部署的多模态工作流）
- 目标：筛选当日近期活跃、可复用、可解释机制清晰、可沉淀为 SKILL 的对象
- 输出：3 个升级点 + 一份可直接复用的 `output/SKILL.md`

## 候选对象与证据

### 1. browser-use / browser-use（优选）
- 用途：跨模型浏览器自动化 agent（基于 Playwright）
- 核心功能：多模型协调、浏览器动作规划与执行、会话式网页交互
- 工作原理：LLM 规划 -> 浏览器动作树 -> 执行回执 -> 状态反馈闭环
- 边界：对网页结构变化敏感；权限与反爬机制受限
- 热度证据：发布页显示近期版本与兼容性修复（如 Chrome 145+ 相关兼容）
- 来源：`https://github.com/browser-use/browser-use`
- 升级价值：可转为 codex 自动化调用“网页抓取+动作执行+重试”模板

### 2. agno / agno（优选）
- 用途：构建可组合的 Agent、工具链与记忆系统
- 核心功能：Team/Workflow、MemoryTools、memory 管理操作接口
- 工作原理：工具定义 + 多agent 调度 + 记忆持久化 + 路由策略
- 边界：运行时配置复杂度高；学习曲线较陡
- 热度证据：官方文档与仓库展示持续发布的多模块结构与实践模式
- 来源：`https://github.com/agno-agi/agno`
- 来源文档：`https://agno.verygood.ventures/`
- 升级价值：非常适合形成 Skill 内部流程编排与失败降级标准化模板

### 3. open-webui / open-webui（优选）
- 用途：自托管对话界面与工具调用网关
- 核心功能：本地模型支持、知识库同步、文件系统工具、任务调度与管理增强
- 工作原理：模型入口层 + 插件化工具层 + 会话持久化
- 边界：部署和配置复杂，环境依赖更多
- 热度证据：近期 release 与目录增量同步、任务管理等更新记录
- 来源：`https://github.com/open-webui/open-webui`
- 升级价值：可强化离线优先发布链路和可解释交互能力

### 4. openai/codex（低优先）
- 用途：展示/研究层面的 Codex 实验与生态信息
- 判定：偏展示与说明，生产执行链路与可直接转 Skill 空间小于前三者
- 结论：保留为观察对象，不纳入当前三点升级

## 选择机制

- 选择了 3 个候选作为升级对象：browser-use、agno、open-webui
- 评价标准：近期活跃、可实现自动化闭环、可定义边界与 fallback、对 Codex 重复价值高
