## 候选对象与筛选证据

### 1. openai/openai-agents-python（入选）

- 用途：OpenAI 多智能体执行框架，覆盖工具调用、模型执行与运行时组织。
- 核心功能：支持工具链路的严格执行约束与 JSON 契约校验。
- 工作原理：通过 Runner/Agent Runtime 组织 step 执行，并对 tool input/output 与执行结果进行序列化约束。
- 边界：模型兼容性依赖和模型参数映射需要结合本地模型策略统一。
- 来源与热度证据：
  - GitHub API 元数据：`stars=27,342`（2026-06-23 日采样）
  - 最近更新：`2026-06-22T22:34:45Z`
  - 最新 Release：`v0.17.6`（`2026-06-19T06:03:31Z`）
  - Release 摘要：添加 `pre-approval tool input guardrails`、`strict JSON-compatible contract`。
- 结论：适合转化为可复用 Skill，价值在于减少工具调用失败与不可解释行为。

### 2. browser-use/browser-use（入选）

- 用途：LLM 驱动的浏览器自动化代理框架，适配表单/采集/多步交互。
- 核心功能：支持浏览器动作规划、DOM 交互、provider 选择。
- 工作原理：模型生成动作意图后由执行层调用浏览器会话并回传上下文。
- 边界：页面结构变更会触发高失败率；对异步模型返回波动敏感。
- 来源与热度证据：
  - GitHub API 元数据：`stars=100,134`
  - 最近更新：`2026-06-20T18:21:29Z`
  - 最新 Release：`0.13.2`（`2026-06-12T22:45:04Z`）
  - Release 摘要：新增 provider-prefixed model、发布动作加上 release env 门禁。
- 结论：适合转化为 Skill，价值在于执行链路稳定性和可降级策略。

### 3. openai/codex（入选）

- 用途：Codex CLI 与插件生态的官方代码仓库，直接反映 Codex 工作流能力演进。
- 核心功能：插件分发与管理、使用额度展示与兑换、CLI 使用节奏控制。
- 工作原理：在本地 CLI/插件链路上引入版本化行为与状态能力入口。
- 边界：属于工具层演进，升级过快时可能影响本地运行环境兼容。
- 来源与热度证据：
  - GitHub API 元数据：`stars=92,728`
  - 最近更新：`2026-06-23T00:02:41Z`
  - 最新 Release：`rust-v0.142.0`（`2026-06-22T22:19:53Z`）
  - Release 摘要：`/usage` 增强、插件按类型组织。
- 结论：适合转化为 Skill：可做“版本兼容 + 发布后回归 + 使用上限提示”模块。
